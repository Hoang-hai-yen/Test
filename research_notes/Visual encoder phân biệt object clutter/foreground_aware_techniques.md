# Non-Encoder-Swap Techniques for Foreground-vs-Clutter Discrimination in Embedding/Cosine-Similarity Matching Pipelines

## Foreground-masked / saliency-weighted pooling instead of global average pooling

### Takeaway
There is a well-established line of unsupervised-object-discovery research (LOST → Deep Spectral Methods → TokenCut → CutLER → FOUND) showing that self-supervised ViT (DINO/DINOv2) patch features and attention maps already carry enough foreground/background signal to build a mask without any labels or SAM, and this mask can then be used to pool only foreground patch tokens before computing the embedding used for matching. A more sophisticated alternative (MaskInversion) shows that naive masked-average-pooling of patch tokens is a real but imperfect baseline, and optimization-based localized-embedding extraction outperforms it.

### Cited Findings
- LOST (Siméoni et al., BMVC 2021, "Localizing Objects with Self-Supervised Transformers and no Labels") finds object regions from a single image using activation features of a self-supervised ViT, with no external object proposals or dataset-level exploration required; it outperforms prior object-discovery baselines by up to 8 CorLoc points on PASCAL VOC 2012, and training a class-agnostic detector on its discovered boxes adds another 7 points. — [arXiv:2109.14279](https://arxiv.org/abs/2109.14279), [GitHub](https://github.com/valeoai/LOST)
- Deep Spectral Methods (Melas-Kyriazi et al., CVPR 2022) reframes unsupervised segmentation/localization as graph partitioning: eigenvectors of the Laplacian of a feature-affinity matrix built from self-supervised (DINO) features already decompose an image into meaningful object/background segments, and this simple spectral method outperforms prior state of the art on Pascal VOC and MS-COCO unsupervised localization/segmentation; the authors explicitly note it is usable for background removal/compositing. — [arXiv:2205.07839](https://arxiv.org/abs/2205.07839), [GitHub](https://github.com/lukemelas/deep-spectral-segmentation), [project page](https://lukemelas.github.io/deep-spectral-segmentation/)
- TokenCut formulates unsupervised object discovery as a graph-partitioning (normalized-cut) problem directly on transformer (DINO) token features, in a training-free framework, to segment the foreground object from background. — [search summary citing TokenCut methodology](https://www.emergentmind.com/topics/vision-transformer-dinov2)
- CutLER (Wang et al., CVPR 2023, "Cut and Learn for Unsupervised Object Detection and Instance Segmentation") uses a MaskCut procedure (built on self-supervised ViT features) to generate coarse multi-object masks with no human annotation, then self-trains a detector on them; it improves unsupervised detection by >2.7x across 11 benchmarks spanning natural images, video, paintings, and sketches, and shows strong robustness to domain shift; with fine-tuning it surpasses a MoCo-v2-initialized low-shot detector by 7.3 APbox / 6.6 APmask on COCO at 5% labels. — [arXiv:2301.11320](https://arxiv.org/abs/2301.11320), [GitHub](https://github.com/facebookresearch/CutLER), [project page](https://people.eecs.berkeley.edu/~xdwang/projects/CutLER)
- FOUND (Siméoni et al., CVPR 2023, "Unsupervised Object Localization: Observing the Background to Discover Objects") inverts the usual approach: it looks for the *background* class (the least-activated / most "background-like" patches in self-supervised ViT features) and treats the remainder as foreground; it uses "a simple model made of a single conv1×1 initialized with coarse background masks extracted from self-supervised patch-based representations," which is then quickly refined — i.e., it is not fully training-free but needs only very fast, lightweight training of a 1x1 conv head, not backbone fine-tuning. It reports state-of-the-art results on unsupervised saliency detection and object-discovery benchmarks. — [arXiv:2212.07834](https://arxiv.org/abs/2212.07834)
- DINOv2's self-attention consistently highlights relevant/salient regions; attention density from the CLS token can be used to identify foreground clusters, which can then be agglomeratively merged and CRF-refined into segmentation/saliency/detection outputs — no fine-tuning of the ViT is required; frozen backbone attention is sufficient. — [Vision Transformer DINOv2 overview](https://www.emergentmind.com/topics/vision-transformer-dinov2)
- MaskInversion (2024, "Localized Embeddings via Optimization of Explainability Maps") directly targets the problem of extracting localized, object-level embeddings from foundation models such as CLIP/DINO for object-vs-background discrimination, arguing that while these models are good at whole-image embeddings, getting a discriminative embedding for a specific region is underexplored. It contrasts its optimization-based (explainability-map-inversion) approach with plain masked-average-pooling of patch tokens, arguing simple masked pooling suffers from information loss, background contamination (imperfect suppression of background tokens), and limited discriminability from unweighted averaging; MaskInversion instead optimizes an embedding by inverting an explainability map for the masked region, yielding representations reported as better than naive masking for retrieval/object-level tasks. — [arXiv:2407.20034](https://arxiv.org/abs/2407.20034)
- A general finding across the vision-language/segmentation literature: masked average pooling (MAP) — computing the mean feature vector only over encoder patches overlapping a given mask, then L2-normalizing — is a standard, simple technique already used to align language/vision features to object regions, and generalized-mean pooling (GeM) is used as a refinement over plain average pooling for compact patch-embedding representations. — [OTAS paper](https://arxiv.org/pdf/2507.08851)
- DINOv2/ViT internals contain a small fraction (~2%) of "high-norm" outlier tokens (roughly 10x the norm of normal tokens), concentrated in the middle layers, which occur disproportionately in visually uniform/low-information regions such as background clutter; these outliers store little local patch information and corrupt raw attention-map interpretability. Adding "register" tokens (trained-in extra tokens that absorb this global-information role) removes these artifacts and produces smoother, more interpretable attention/feature maps, improving dense-prediction quality. This is directly relevant because it means naive CLS-attention-based foreground masks from vanilla DINOv2 (without registers) can be corrupted by these artifact tokens, especially over homogeneous clutter/background regions. — [Vision Transformers Need Registers, arXiv:2309.16588](https://arxiv.org/pdf/2309.16588), [Vision Transformers Don't Need Trained Registers, arXiv:2506.08010](https://arxiv.org/html/2506.08010v2)

### Inferences
- For a drone/aerial detection pipeline, the cheapest version of this technique is: run the crop through DINOv2, take the CLS-token attention map (or an inter-patch similarity/spectral decomposition à la Deep Spectral Methods) as a cheap foreground mask, then do masked-average pooling of patch tokens restricted to the foreground mask before the cosine-similarity match — this requires no extra model, no SAM, and no training, only a forward pass that is already being computed (attention weights come "for free" alongside the patch tokens).
- Because DINOv2 (without registers) has known high-norm artifact tokens concentrated in flat/textured background regions, using the DINOv2-with-registers checkpoint (available on Hugging Face) is likely to give a materially cleaner attention-based foreground mask than vanilla DINOv2 for exactly the kind of "textured clutter" (dry leaves, dirt, rocks) failure mode described in the problem statement — this is an inference bridging the registers finding and the pooling-quality goal, not a claim directly tested for this application in the sources found.
- FOUND's finding that background is easier to characterize than foreground (least-activated / most self-similar patches) may be a more robust signal for masking out background clutter than trying to directly threshold "foreground-ness," since natural clutter (dirt, leaves) is exactly the kind of locally homogeneous, low-salience content that FOUND-style background detectors are designed to catch.

### Gaps
- No source directly benchmarks masked/foreground-weighted pooling vs. plain global-average-pooling specifically for cosine-similarity *few-shot prototype matching* (as opposed to segmentation/localization benchmarks like CorLoc or mIoU). The improvement in object-vs-clutter cosine-similarity discrimination specifically is inferred, not directly measured, from the segmentation-quality literature.
- Quantitative CorLoc/mIoU numbers for FOUND vs. LOST/TokenCut/Deep Spectral Methods were not retrievable from the fetched sources (the abstract-only crawl did not surface the results table); only that FOUND reports state-of-the-art results is confirmed.
- No source found specifically evaluating attention-map-based masking robustness under aerial/overhead viewpoints (all cited unsupervised-object-discovery work is evaluated on ground-level natural image benchmarks like PASCAL VOC/COCO, not aerial/drone imagery).

## SAM/SAM2 as a pre-processing step to isolate the target object mask before embedding

### Takeaway
Using SAM (or SAM2) to segment/mask a crop before feeding it to an embedding encoder is a known and actively used pattern, especially combined with DINOv2/CLIP features for one-shot/few-shot object matching and personalization (PerSAM, Matcher), but it adds a second heavyweight model to the pipeline and its own zero-shot failure modes (small/tiny objects, domain shift, background-artifact segmentation), so latency and domain-robustness tradeoffs are real and documented, even though direct re-ID-pipeline latency/accuracy ablation numbers were not found.

### Cited Findings
- PerSAM ("Personalize Segment Anything Model with One Shot," ICLR 2024) is a training-free method that personalizes SAM using a single reference image+mask: it derives a positive/negative location prior for the target concept, then uses "target-guided attention" and "target-semantic prompting" to get SAM to segment the same personalized concept in new images without any training; an optional fine-tuned variant (PerSAM-F) tunes only 2 parameters in about 10 seconds to fix multi-scale segmentation ambiguity. This is essentially the "SAM + one-shot prototype matching" pattern applied at the mask level. — [arXiv:2305.03048](https://arxiv.org/abs/2305.03048)
- Matcher ("Segment Anything with One Shot Using All-Purpose Feature Matching," ICLR 2024) is a training-free framework that explicitly combines an all-purpose feature extractor (DINOv2) with a class-agnostic segmenter (SAM): it computes a correspondence matrix between reference and target image features (bidirectional patch-level matching), uses this to generate prompts for SAM, and does instance-level matching via Earth Mover's Distance with purity/coverage metrics; it achieves 52.7% mIoU on COCO-20 for one-shot semantic segmentation, beating the prior state-of-the-art specialist model by 1.6 points, without any task-specific training. — [arXiv:2305.13310](https://arxiv.org/abs/2305.13310), [GitHub](https://github.com/aim-uofa/matcher)
- SAM itself (the original Segment Anything Model) is described as a category-agnostic interactive segmentation model trained on 1.1 billion masks (SA-1B dataset), comprising an image encoder (ViT), a prompt encoder, and a mask decoder; it has become a widely-used foundation for few-shot segmentation pipelines, including for domain-specific tasks like medical imaging (SAM-RSP, SAM-MPA, AGSAM). — [general SAM background from search aggregation](https://towardsdatascience.com/sam-segment-anything-model-4b25a47245f2/)
- SAM's zero-shot mask quality is known to be imperfect: even its higher-quality successor "Segment Anything in High Quality" (HQ-SAM) notes SAM's prediction quality "falls short in many cases, particularly when dealing with objects that have intricate structures," and HQ-SAM itself still has documented failure cases in extremely dark environments or with very tiny/thin structures (e.g., "very tiny metal rods"); more generally SAM tends to over-segment background artifacts and to fail (low recall) when relying on ambiguous referring/contextual cues, and its zero-shot ability degrades on out-of-distribution/domain-shifted imagery (explicitly demonstrated for medical images, with complete failure on some structured targets like blood vessels). — [arXiv:2306.01567 (HQ-SAM)](https://arxiv.org/abs/2306.01567), [SAM medical zero-shot study, PMC10252742](https://www.ncbi.nlm.nih.gov/pmc/articles/PMC10252742/)
- Latency data for SAM2 on constrained/edge hardware (a reasonable proxy for what a drone/embedded pipeline would face): mobile-oriented variants (TinySAM, MobileSAM) run at ~264–267 ms/frame (≈3.7 FPS, ~332–346 MB memory) on edge hardware, well short of real-time (21+ FPS); a TensorRT/FP16-optimized SAM2 implementation reaches ~123 ms/frame (up to 3x faster than ONNX Runtime); an extremely constrained in-sensor quantized variant, PicoSAM2 (1.22 MB), achieves 14.3 ms on IMX500 hardware but with architectural trade-offs (reduced accuracy/generality implied); on capable GPUs, users report SAM2 itself feels "real-time" at approximately 44 FPS. — [PicoSAM2, arXiv:2506.18807](https://arxiv.org/html/2506.18807), [SAM2-edge-cpp GitHub](https://github.com/umitkacar/sam2-edge-cpp), [TIER IV TensorRT blog](https://medium.com/tier-iv-tech-blog/high-performance-sam2-inference-framework-with-tensorrt-9b01dbab4bf7), [SAM2 GitHub issue #159](https://github.com/facebookresearch/sam2/issues/159)

### Inferences
- The "encoder features generate the prompt, SAM refines the mask" pattern (Matcher, PerSAM) is a more sophisticated and more validated version of the "SAM as preprocessing" idea than naively running SAM's automatic mask generator on every crop; for a few-shot prototype-matching pipeline, prompting SAM with a point/box derived from the existing detector output (rather than running full automatic segmentation) would be both cheaper and more targeted, closer to how PerSAM/Matcher use it.
- Given SAM/SAM2's documented failure modes on tiny objects and domain-shifted imagery, and that aerial/drone crops of small targets against dirt/leaf clutter are plausibly both "small object" and "domain-shifted" relative to SAM's training distribution (SA-1B, largely ground-level/natural photos), SAM segmentation quality on this specific use case is not guaranteed to be reliable without validation — this is inferred risk, not a tested result for this domain.
- Running full SAM/SAM2 per-candidate-crop is a real latency cost (tens to hundreds of ms per frame even in optimized/edge configurations) that is likely to dominate a pipeline that also runs a ViT encoder per crop; this makes DINOv2's own attention-derived mask (see the "attention maps" section above/below) an attractive latency-free alternative or fallback to SAM specifically because it requires no second model or extra forward pass.

### Gaps
- No source was found that reports a direct, controlled latency/accuracy ablation of "SAM-masked crop → embed → cosine-similarity match" vs. plain bounding-box crop → embed, in a re-identification, few-shot detection, or tracking pipeline specifically. The latency numbers found are for SAM2 segmentation quality/speed in isolation, not integrated into an embedding-matching pipeline, and the accuracy benefit (if any) of SAM-masking before embedding for cosine-similarity matching specifically was not directly quantified in any retrieved source.
- No source specifically addresses SAM/SAM2 mask quality on aerial/overhead drone imagery of small ground objects against natural clutter (leaves/dirt/rocks) — this is a meaningful gap given the target application.

## Lightweight fine-tuning of DINOv2 for object-vs-clutter discrimination (LoRA, adapters, linear probes)

### Takeaway
DINOv2 features already transfer strongly with just a frozen backbone + linear probe or lightweight adapter, and parameter-efficient fine-tuning (LoRA on attention Q/V projections) is a documented, low-cost way to adapt DINOv2 to a new fine-grained discrimination task — but there is also a real, reported failure mode where naive fine-tuning of the backbone (even just adding a trainable head and fine-tuning end-to-end) can make retrieval performance *worse* than the frozen pretrained model, underscoring that this path requires care (freezing most of the backbone, small learning rates, adequate/well-curated data) rather than being a guaranteed win.

### Cited Findings
- DINOv2 features are described as broadly adaptable and competitive even "frozen" via linear probe, or in few-shot settings, achieving state-of-the-art transfer with frozen features + linear probes on ImageNet-1k and out-of-domain sets; a common adaptation pattern is to freeze every DINOv2 layer except for a small adapter plus the linear probe, so only lightweight heads/adapters are trained — reducing both compute and overfitting risk. — [DINOv2 paper, arXiv:2304.07193](https://arxiv.org/html/2304.07193v2), [emergentmind DINOv2 backbone overview](https://www.emergentmind.com/topics/dinov2-backbone)
- "Parameter-Efficient Fine-Tuning of DINOv2 for Large-Scale Font Classification" (2026) applies LoRA specifically to the query/value projection matrices in DINOv2's attention layers, using rank r=8, scaling factor α=16 — about 150K trainable parameters, under 0.2% of total model size. On a 394-class fine-grained visual discrimination task, results scaled clearly with data quantity: an earlier, smaller dataset (~9,400 images total) yielded only 59% accuracy, while scaling to ~575 synthetic images per class (across 394 classes) raised top-1 accuracy to ~86%. Training used standard PyTorch/Hugging Face infrastructure, LR 1e-4, batch size 32, 100 epochs, FP16 mixed precision — i.e., modest, single-GPU-class compute. The authors highlight that synthetic data works well when augmentations match deployment conditions, and that iterative dataset curation (removing near-duplicate/near-identical classes) was important. — [arXiv:2602.13889](https://arxiv.org/html/2602.13889v1)
- A public GitHub issue on the official DINOv2 repo (facebookresearch/dinov2 #559) reports a case where a user fine-tuned DINOv2 ViT-L/14 (backbone + a new trainable 256-D linear embedding head) on a jewelry image-retrieval dataset and got *worse* cosine-similarity retrieval results than using the pretrained frozen model directly. No maintainer/community diagnosis had been posted as of the time this issue was checked, so the root cause (overfitting, catastrophic forgetting, learning-rate too high, insufficient data, etc.) is undetermined from this source — but the existence of this reported failure is itself a data point that unconstrained backbone fine-tuning is risky. — [GitHub facebookresearch/dinov2 issue #559](https://github.com/facebookresearch/dinov2/issues/559)
- LoRA (Low-Rank Adaptation), originally developed for large language models, is used for DINOv2/DINOv3 exactly because it freezes the pretrained backbone weights and injects small trainable low-rank decomposition matrices (typically into attention and feed-forward blocks), drastically cutting trainable-parameter count and making adaptation of large frozen vision backbones computationally cheap. — [general LoRA framing](https://huggingface.co/blog/lora), search-aggregated findings
- Existing open-source frameworks apply this pattern directly to DINOv2/DINOv3 for embedding/retrieval tasks: `RobvanGastel/dinov3-finetune` finetunes DINOv2/DINOv3 encoder weights with LoRA plus a lightweight 1x1-conv decoder head, explicitly framed as making finetuning to new tasks easier without touching the original encoder weights; `fangzhensheng/vembed-factory` documents a DINOv3-based embedding pipeline supporting Gradient Cache, Matryoshka representation learning, and LoRA for large-scale multimodal search/retrieval, with LoRA specifically used to reduce VRAM usage during fine-tuning. — [dinov3-finetune GitHub](https://github.com/RobvanGastel/dinov3-finetune), [vembed-factory GitHub](https://github.com/fangzhensheng/vembed-factory)
- Reported real-world results from adapting DINOv3 with fine-tuning for e-commerce product retrieval: DINOv3-ViT-B/16 fine-tuned for retrieval achieved 83.13% Recall@1, a 17.81-point improvement over the zero-shot (frozen) model — indicating that, done correctly, targeted fine-tuning of a DINO-family backbone can yield large retrieval-quality gains over the frozen baseline. — [search-aggregated finding, referencing DINOv3 retrieval fine-tuning results](https://github.com/fangzhensheng/vembed-factory)
- On hard-negative mining specifically for metric-learning losses (relevant to constructing the "object vs. clutter" training signal): the historical consensus was that training on the very hardest negatives leads to bad/unstable training behavior, precisely because those hardest negatives are the cases where the current embedding space fails most; more recent metric-learning work shows a corrected loss formulation makes training with hard negatives feasible and yields image-retrieval performance that outperforms prior state of the art; a common practical compromise is training with *semi-hard* negatives — negatives that violate the triplet margin but are farther from the anchor than the true positive. — ["Hard negative examples are hard, but useful," arXiv:2007.12749](https://arxiv.org/pdf/2007.12749), [Wikipedia triplet loss overview](https://en.wikipedia.org/wiki/Triplet_loss)

### Inferences
- The combination of these sources suggests the safest low-effort path is: freeze the DINOv2 backbone entirely, train only a small projection/adapter head (or LoRA on attention Q/V matrices) with a contrastive/triplet loss using object crops as positives and mined background-clutter crops (dirt/leaves/rocks) as hard negatives — this mirrors both the font-classification PEFT paper's approach and the general "frozen backbone + adapter" DINOv2 usage pattern, and should avoid the catastrophic-forgetting-style failure seen in the jewelry retrieval GitHub issue (which fine-tuned the full backbone + head).
- Data requirements appear to scale with class/task granularity rather than being fixed: the font-classification paper needed only modest per-class image counts (a few hundred) to reach strong (86%) accuracy on a genuinely fine-grained 394-way task, suggesting that a simpler binary/coarse "object vs. natural clutter" discrimination task for a drone pipeline could plausibly require substantially less labeled data — though this is an extrapolation, not a directly reported number for a binary object-vs-background task.

### Gaps
- No source gives a concrete "how many images are needed" figure specifically for a binary or few-class "object vs. background-clutter" contrastive/triplet fine-tuning task (as opposed to the 394-class font task or general retrieval fine-tuning) — the closest data points (font classification, e-commerce retrieval) are for different, more fine-grained tasks.
- No root-cause diagnosis was retrievable for why the jewelry-retrieval DINOv2 fine-tune underperformed the frozen baseline (the GitHub issue had not received a maintainer response at the time of this research), so it should be treated as a cautionary anecdote rather than a diagnosed lesson.
- No source directly compares LoRA-adapted DINOv2 vs. a from-scratch/simple linear-probe approach specifically for foreground-object-vs-natural-clutter discrimination; the LoRA evidence found is from adjacent tasks (font classification, product retrieval).

## Two-stage architectures: embedding filter + secondary verifier network with hard-negative mining

### Takeaway
Two-stage "propose with a fast/coarse matcher, then verify with a dedicated classifier trained on hard negatives" is a long-established and still actively used pattern in single/multi-object tracking (Siamese-tracker verification networks, DaSiamRPN-style distractor-aware modules) and in multi-object tracking's appearance re-ID modules (ByteTrack/BoT-SORT), directly supporting the proposed pattern of adding a small binary object-vs-clutter verifier trained on the pipeline's own false positives.

### Cited Findings
- In two-stage visual object tracking, a dedicated "verification network," architected as a Siamese network specifically to reduce semantic ambiguity in binary classification, is combined with hard-negative mining to bridge the gap between a fast candidate-proposal sub-network and a more discriminative verification sub-network — i.e., exactly the "cheap filter + verifier trained on hard negatives" pattern. — [Two-stage visual object tracking survey material](https://arxiv.org/pdf/2104.13648)
- DaSiamRPN (a well-known Siamese-tracker line) improves discriminative ability by collecting hard negative samples during offline training and adds a "distractor-aware module" that continuously discovers hard negative distractors online, updating the tracker to reject visually similar-but-wrong objects during inference. — [Visual Object Tracking survey citing DaSiamRPN's distractor-aware design](https://arxiv.org/pdf/2112.02838)
- In practical tracker deployment, detections with sufficiently high similarity/confidence scores that turn out to be wrong are explicitly used as hard-negative samples to incrementally update the tracker/verifier online — an operational version of "mining hard negatives from the pipeline's own false positives," matching the proposed approach directly. — [Cascaded Regression Tracking survey material](https://arxiv.org/pdf/2006.10336)
- BoT-SORT and ByteTrack (widely used real-world multi-object trackers) combine motion-based matching (Kalman-filter IoU distance) with a separate appearance re-ID embedding matched via cosine distance; BoT-SORT maintains a rolling buffer (default 50-frame history) of normalized re-ID embeddings per track with exponential-moving-average smoothing, and uses two independent thresholds — `proximity_thresh` (IoU distance) and `appearance_thresh` (cosine-similarity threshold, default 0.3) — meaning the appearance/embedding signal already functions as a secondary verification gate layered on top of a cheaper motion-based candidate filter, structurally analogous to the proposed embedding-filter-then-verifier design. — [BoT-SORT paper, arXiv:2206.14651](https://arxiv.org/html/arXiv:2206.14651), [Ultralytics BoT-SORT docs](https://docs.ultralytics.com/reference/trackers/bot_sort)

### Inferences
- The tracking/re-ID literature strongly supports the proposed pattern as "standard": a fast embedding/cosine-similarity match (analogous to the motion/IoU stage) narrows candidates, and a dedicated, more discriminative verifier (analogous to a Siamese verification network or an appearance re-ID gate) trained with actively-mined hard negatives (mirroring DaSiamRPN's online distractor mining and the "use current false positives as new hard negatives" tracker-update pattern) then rejects clutter that passed the first-stage threshold. For the aerial pipeline, this maps directly onto: keep the existing DINOv2-embedding cosine-similarity stage as a coarse filter, then train a small binary classifier (or a second-stage triplet-tuned head) on hard negatives = the pipeline's own clutter false positives, refreshed periodically as new false positives are collected, exactly matching the DaSiamRPN/tracker-update pattern.

### Gaps
- No source found gives a concrete architecture size, training-data volume, or accuracy delta for a standalone binary "object vs. clutter" verifier head specifically layered on frozen DINOv2/CLIP/SigLIP embeddings outside of the tracking literature; the verification-network evidence here is drawn from general SOT/MOT tracking research (which typically verifies "same object across frames," a related but not identical task to "real object vs. natural-texture clutter in a single frame").
- No specific numeric accuracy/false-positive-rate improvement figures were retrieved for BoT-SORT's or DaSiamRPN's re-ID/verification stage in isolation (i.e., how much the second-stage verifier reduces false positives compared to the first-stage embedding/motion match alone).

## DINOv2's own attention maps / patch tokens as an implicit, SAM-free foreground signal

### Takeaway
This is well supported: DINO/DINOv2's self-attention is widely documented to emerge, without any segmentation supervision, as a strong foreground-localization signal, and this is the basis of an entire family of training-free or near-training-free unsupervised object-discovery methods (LOST, TokenCut, Deep Spectral Methods, FOUND) — making it a genuinely lower-cost alternative to running a separate SAM model, with the important caveat that vanilla DINOv2 has documented "high-norm artifact token" corruption of raw attention maps, mitigated by using DINOv2-with-registers.

### Cited Findings
- DINO was the original source of this observation: self-supervised ViTs trained with DINO learn to perform a form of latent semantic/foreground segmentation "for free," a property absent in supervised ViT counterparts — this observation is what LOST, TokenCut, and subsequent spectral/discovery methods are all built on. — [search-aggregated summary of the LOST/DINO lineage](https://www.researchgate.net/publication/359436214_Unsupervised_Salient_Object_Detection_with_Spectral_Cluster_Voting), [arXiv:2109.14279 (LOST)](https://arxiv.org/abs/2109.14279)
- For DINOv2 specifically: attention density concentrated around the CLS token reliably marks foreground clusters; this attention-derived foreground/background split can be turned into a "semantic distance" between regions, and regions can be agglomeratively merged up to that distance to yield an image-relative semantic segmentation usable for object detection, saliency detection, or semantic segmentation — and critically, no fine-tuning of the ViT is required; frozen-backbone features suffice. — [Vision Transformer DINOv2 overview / emergentmind](https://www.emergentmind.com/topics/vision-transformer-dinov2)
- The predominant unsupervised-object-discovery approach is exactly this: distinguish objects by graph-partitioning-style segmentation applied directly to the DINO activation/attention map, separating foreground objects from background without any external segmentation model such as SAM. — [same emergentmind DINOv2 aggregation](https://www.emergentmind.com/topics/vision-transformer-dinov2)
- However, DINOv2 (and ViTs generally) exhibit high-norm "outlier" tokens — about 2% of tokens, ~10x the norm of typical tokens, concentrated in the middle network layers — that appear disproportionately in visually redundant/uniform regions (i.e., the kind of homogeneous background clutter texture described in the problem: dirt, leaves). These tokens carry little local patch information and are known to corrupt/spike raw attention-map visualizations, making a naive "just threshold CLS attention" foreground mask noisier than it should be. The fix proposed and validated in the literature is adding trained "register" tokens to the ViT, which absorb this global bookkeeping role and yield attention maps that are smoother and more usable for dense-prediction/segmentation-style tasks; a DINOv2-with-registers checkpoint exists and is documented on Hugging Face. — [Vision Transformers Need Registers, arXiv:2309.16588](https://arxiv.org/pdf/2309.16588), [Vision Transformers Don't Need Trained Registers, arXiv:2506.08010](https://arxiv.org/html/2506.08010v2), [DINOv2 with Registers, Hugging Face docs](https://huggingface.co/docs/transformers/en/model_doc/dinov2_with_registers)

### Inferences
- Of all the techniques surveyed, this is the cheapest to implement for the described pipeline: it requires no new model (no SAM), no training, and no additional forward pass, because the attention weights are already computed as a byproduct of the existing DINOv2 forward pass used to produce the pooled embedding. Switching to (or adding) a DINOv2-with-registers checkpoint specifically to get cleaner attention maps is a near-zero-cost upgrade path if not already in use, given the documented artifact-token problem in vanilla DINOv2.
- Because FOUND's core insight is that background is often the more reliably identifiable class from ViT features (least-activated/most self-similar patches), a background-first thresholding strategy on DINOv2 attention/self-similarity, rather than a foreground-first strategy, may be the more robust cheap heuristic for the drone use case — worth testing against simple CLS-attention thresholding.

### Gaps
- No source was found benchmarking DINOv2 attention-map-derived masking specifically against SAM-derived masking for downstream cosine-similarity matching accuracy (only segmentation-quality benchmarks like CorLoc/mIoU on ground-level image datasets were found, not head-to-head "which mask source improves matching precision more" studies).
- No source specifically tested attention-map-based foreground masking on overhead/aerial imagery, where object scale, viewing angle, and background statistics differ substantially from the ground-level natural-image benchmarks (PASCAL VOC, COCO) used in all cited unsupervised-object-discovery papers.

## Rough relative implementation effort/cost of each technique

### Takeaway
The techniques form a clear effort ladder from pure inference-time changes (attention-based masked pooling) through moderate-effort-but-no-training additions (SAM-based mask preprocessing) to genuinely training-requiring approaches (LoRA/adapter fine-tuning, two-stage verifier networks), and the literature suggests starting with the cheapest, already-computed signal (DINOv2 attention) before adding new models or training pipelines.

### Cited Findings
- Attention-map/patch-token-based foreground masking (LOST, TokenCut, Deep Spectral Methods, or simple CLS-attention thresholding on the existing DINOv2 forward pass) requires no additional labeled data and, per the sources above, no fine-tuning of the ViT — several of these methods are explicitly described as training-free, operating on a single image using only pre-trained self-supervised features. — [arXiv:2109.14279](https://arxiv.org/abs/2109.14279), [arXiv:2205.07839](https://arxiv.org/abs/2205.07839)
- FOUND sits one notch higher in effort: it needs a small conv1x1 head to be quickly trained/refined from coarse background masks — described as "fast training," implying lightweight/cheap but not literally zero training cost. — [arXiv:2212.07834](https://arxiv.org/abs/2212.07834)
- SAM/SAM2-based mask preprocessing (PerSAM, Matcher) can be used training-free (PerSAM's base variant, Matcher) for one-shot personalization/matching, but adds substantial inference cost from running a second, large segmentation model per crop — edge/mobile SAM2 variants run at roughly 14–267 ms/frame depending on optimization level and hardware, a nontrivial addition on top of the existing encoder's own forward pass. — [arXiv:2305.03048](https://arxiv.org/abs/2305.03048), [arXiv:2305.13310](https://arxiv.org/abs/2305.13310), [arXiv:2506.18807](https://arxiv.org/html/2506.18807)
- LoRA/adapter fine-tuning of DINOv2 requires labeled/curated data (positive object crops and, ideally, hard-negative clutter crops) plus a training loop, but is deliberately lightweight in compute: the font-classification PEFT example trained ~150K parameters (under 0.2% of the model) on a single accelerator (CUDA/MPS) with a standard 100-epoch run, and needed on the order of a few hundred images per class to reach strong accuracy for a genuinely fine-grained (394-way) task. — [arXiv:2602.13889](https://arxiv.org/html/2602.13889v1)
- Two-stage verifier networks require both labeled/mined data (positive objects + actively mined hard-negative false positives from the pipeline itself) and a training loop for the verifier, mirroring the tracking literature's online hard-negative-mining/distractor-aware-module pattern — this is the highest-effort option among those surveyed, since it requires an operational loop for continuously collecting and retraining on the pipeline's own false positives, not just a one-time dataset. — [DaSiamRPN-related survey material](https://arxiv.org/pdf/2112.02838), [Cascaded Regression Tracking](https://arxiv.org/pdf/2006.10336)

### Inferences
- A natural low-risk rollout order, from the evidence gathered: (1) switch/verify use of DINOv2-with-registers and add attention-map-based masked pooling — pure inference-time change, no data or training needed; (2) if that's insufficient, add a lightweight LoRA/adapter head trained with triplet/contrastive loss on object-vs-mined-clutter crops — needs a modest labeled dataset (plausibly low hundreds of images based on the font-classification data point, though not confirmed for this exact binary task) and a single-GPU training run; (3) only if still insufficient, invest in a full two-stage verifier network with an ongoing hard-negative-mining loop from the pipeline's own false positives — the highest-effort but most targeted fix, directly modeled on proven SOT/MOT tracker verification patterns. SAM/SAM2 preprocessing sits as a parallel, non-training option but carries meaningful per-crop latency cost and unverified accuracy benefit for this specific domain, making it a good candidate for a quick offline accuracy experiment before committing to it as a production inference-time dependency.

### Gaps
- No source provided a unified, apples-to-apples cost/accuracy comparison across all these techniques on the same task/dataset; the effort ranking above is inferred by combining separate sources for each technique rather than read directly from a single comparative study.
